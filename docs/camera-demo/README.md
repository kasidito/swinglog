# กล้องแนวตั้งและตัวอย่างผลตี

แท็บ **วิดีโอ → เปิดกล้องพร้อมกรอบจัดตำแหน่ง** เริ่มที่ 9:16 กรอบนี้เป็นพื้นที่ที่บันทึกจริง ไม่ใช่การยืดภาพแนวนอนให้เต็มจอ คำแนะนำพับไว้ที่ “วิธีตั้ง” และแสดงนอกภาพ เลือกด้านหน้า/ด้านหลังตามสิ่งที่ต้องการดู และตั้งค่ามือซ้าย/ขวาที่เฟืองเดิม

## พฤติกรรมกล้อง

- ขอภาพกล้องหลังแนวตั้งด้วย `ideal` constraints แล้วใช้ขนาดที่กล้องส่งมาจริง ถ้าสัดส่วนต่างกัน ให้เลื่อนกรอบซ้าย–ขวาหรือบน–ล่างก่อนอัด มีข้อความบอกว่าตัดขอบภาพ
- พรีวิว `object-fit: cover` และ canvas encoder ใช้ crop เดียวกัน ไม่มีไกด์หรือข้อความฝังในไฟล์ ผลวิเคราะห์ใช้ขนาดไฟล์ที่ถอดรหัสจริง
- ไฟล์ผ่าน canvas คงสัดส่วน 9:16 เลือกขนาดเลขคู่โดยไม่ขยายภาพ เช่น source 1280×720 ครอป 405×720 แล้วบันทึก 396×704; source 720×1280 ใช้ native stream ได้โดยตรง เลือก “ภาพเต็มจากกล้อง” เพื่อเก็บพื้นที่ทั้งหมด
- ล็อกกรอบ/มุม/ตำแหน่งครอประหว่างอัด จำกัด 12 วินาที หากขนาด source เปลี่ยน กล้องหยุด หรือแอปถูกพัก จะหยุดและเก็บคลิปบางส่วนพร้อมเหตุผล ปิดกล้องระหว่างอัดคือยกเลิก ไม่ส่งคลิปค้างกลับมา
- ตรวจ `MediaRecorder`, MIME และ `canvas.captureStream` ขณะใช้งาน หากไม่รองรับ แสดงทางเลือกภาพเต็ม กล้องเครื่อง หรือนำเข้าคลิป ไม่อัด native stream แล้วอ้างว่าเป็นครอป
- การขอ 60 FPS จากกล้องและ 30 FPS จาก canvas ไม่รับรอง FPS ถ่ายจริง เวลาในคลิปเป็น encoded timeline โดยประมาณ ไม่เพียงพอสำหรับวัดความเร็วหรือแก้ slow motion

## เดโมและค่าผลลัพธ์

**วิดีโอ → ดูตัวอย่างผลตี** เล่น/หยุด/เริ่มใหม่/เลื่อนเวลาเองได้ มีลูกตรง ลูกโค้ง และติดตามหลุด ใช้ภาพ AI ในโปรเจกต์ประกอบจังหวะกับเส้นทางเรขาคณิตที่เขียนไว้ ไม่ใช่วิดีโอตีจริง ไม่ใช่ physics simulation และไม่ใช่ผลตรวจจับ ภาพกับตัวเลขมีป้ายสมมติ ไม่บันทึกประวัติหรือส่งเข้าเครื่องมือวิเคราะห์จริง เมื่อหลุด เส้นหยุดที่จุดสุดท้ายและทุกค่าช็อตเป็น `—`

คลิปจริงยังแสดง Carry, Club Speed, Ball Speed, Launch Angle, Spin Rate และ Smash Factor เป็น `—` พร้อมเหตุผล แม้มีเส้นลูก 2D ก็ไม่คำนวณระยะหรือความเร็วจากพิกเซล เครื่องมือดูช้า/ลากเส้นยังอยู่ใกล้วิดีโอ ห้องทดลองเดิมให้ค่าศีรษะและลำตัวในภาพ 2D คู่กับเฟรมหลักฐาน

## ข้อมูลและความเข้ากันได้

- `CaptureInfo` ใน `src/capture.ts` เก็บ source/output dimensions, crop พิกัด source ที่ไม่ mirror, mode, recording path, reported FPS, requested canvas FPS, timing limitation และ stop reason ข้อมูลนำเข้าไม่ทราบ FPS; ไม่เดาจากชื่อไฟล์
- `ClipInfo.captureInfo` เป็น optional จึงไม่บังคับให้ประวัติ/รายงานเก่ามี metadata เพิ่ม JSON export เก็บทั้ง dimensions ที่อ่านจริงและสิ่งที่ขอ ไม่อ้างว่าสำเร็จเมื่อขนาดต่างกัน
- `MetricResult` ใน `src/metrics.ts` แยก `image-2d`, `calibrated-estimate`, `simulation`, `unavailable`; ค่าไม่ทราบเป็น `null` ไม่ใช่ศูนย์ `calibrated-estimate` สงวนไว้ ยังไม่มีการผลิตค่าประเภทนี้จากคลิปจริง
- JSON report เพิ่ม `metrics.shot` และ `metrics.pose` โดยรักษา schemaVersion 1 และ fields เดิม ไม่มี bytes วิดีโอหรือ blob URL ไม่มีการเปลี่ยน store/ID ดริล/ความหมายของประวัติ
- ใช้สื่อ AI เดิมใน `public/coaching/` ไม่มีสื่อใหม่ที่ต้องดาวน์โหลด เดโมใช้ PWA precache เดิม ข้อจำกัดการตรวจภาพโดยโปรและผู้เริ่มเล่นยังตาม [เอกสารสื่อเดิม](../coaching/human-review.md)
